# Phase 5.7C — Flutter Capture Adapter

## Status

The capture adapter is implemented as a disposable-fixture-only Flutter test
harness, but fresh PNG generation remains **BLOCKED** in the Codex runtime.
The existing analyzer and golden tests still run successfully. No golden file
was updated and no application source was changed.

## Design

`mcp-server/tests/fixtures/phase5_flutter/test/capture_adapter_test.dart`
renders the real `FixtureDashboard` widget at the five approved logical sizes:

- 360×800
- 430×932
- 768×1024
- 1024×768
- 1440×900

The harness uses Flutter's `RenderRepaintBoundary.toImage` and PNG encoding,
asserts exact output dimensions, refuses collisions, writes through a temporary
file followed by rename, and removes its temporary file on failure. The output
root is restricted to the fixture's repository artifact directory:

`D:\New folder\designforge-ai\mcp-server\.designforge-artifacts\phase5_flutter`

The capture test is skipped unless `DESIGNFORGE_CAPTURE_ROOT` is explicitly set
to that approved path. This keeps ordinary fixture tests read-only.

## Invocation

Use the direct Flutter snapshot because the `.bat` wrapper is not bounded in the
Codex process environment:

```powershell
$env:APPDATA = $isolatedState
$env:LOCALAPPDATA = $isolatedState
$env:PUB_CACHE = "$isolatedState\pub-cache"
$env:DESIGNFORGE_CAPTURE_ROOT = "D:\New folder\designforge-ai\mcp-server\.designforge-artifacts\phase5_flutter"
& C:\src\flutter\bin\cache\dart-sdk\bin\dart.exe --disable-dart-dev `
  C:\src\flutter\bin\cache\flutter_tools.snapshot test --no-pub test/capture_adapter_test.dart
```

The process must be bounded externally, with stdout, stderr, exit code and
elapsed time captured. A timeout is BLOCKED, not PASS.

## Limitations

Phase 5.7D diagnostics disproved a `toImage` hang. Widget construction, layout,
paint, `toImage`, and PNG encoding complete for the first viewport. The process
stops when Dart performs filesystem access for the approved artifact directory
(collision check or temporary write). A test-only stream mode can return real
PNG bytes, but the bounded multi-viewport host writer has not completed safely.
No safe evidence supports claiming five-artifact screenshot generation or
visual acceptance. See `docs/phase-5-7d-capture-diagnostics.md`.

Phase 5.7E adds a test-only stream mode and confined Node host writer. The
writer validated and persisted all five fresh PNGs without modifying source or
golden files. See `docs/phase-5-7e-artifact-persistence.md`.
